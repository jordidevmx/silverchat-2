## 1. Problem understanding

Prompt 14 was written for a greenfield app. SilverChat already runs a brownfield custom `en`/`es` i18n stack and theme/accent persistence, deeply coupled across the codebase. `ADR-002` (Product Owner approved) selects Option A: formalize and harden what exists, with zero new dependencies, rather than introduce `i18next` and an 18-file JSON tree. The remaining real gaps are: no pre-paint FOUC guard, a theme media listener that is always attached instead of only for `system`, `data-theme="light"` instead of removing the attribute for light, missing explicit verification of detection/account-switch behavior, no shared pure `Intl` formatter core/hook, and no adoption of that core by the three existing domain formatter modules.

**In:** items 1–5 of brief §4 — blocking inline FOUC script; theme/accent runtime contract; language detection, `<html lang>` sync and account-switch guarantees; shared `Intl` core + `useFormatters` + adoption in the three domain formatters; automated unit/browser coverage.

## 5. Proposed solution

### 5.1 Pure `Intl` core — `src/lib/formatters.ts`
Export a factory `createFormatters(locale: string)` returning memoizable functions: `formatTime(iso)`, `formatDate(iso)`, `formatLongDate(iso)`, `formatMonthDay(iso)`, `formatGroupDate(iso)`, `formatRelative(iso, now = new Date())` using `Intl.RelativeTimeFormat(locale, {numeric:"auto"})` with the Prompt 14 thresholds (second/minute/hour/day/week then `formatDate`), `formatBytes(bytes)` and `formatDuration(seconds)` preserving `mm:ss` / `h:mm:ss` semantics. The extra date variants preserve the existing domain formatter outputs (`formatMonthDay` = `{day:"2-digit",month:"2-digit"}`; `formatGroupDate` = `{day:"numeric",month:"short",year:"numeric"}`).

**`formatBytes` decimal contract (`AUD-025` G-14):** use two dedicated `Intl.NumberFormat` instances per locale — an integer one for bytes (`{maximumFractionDigits:0}`) and a fixed-one-decimal one for scaled units (`{minimumFractionDigits:1, maximumFractionDigits:1}`), always with a single `format(value)` argument. This yields `formatBytes(0,"en") === "0 B"`, `formatBytes(1536,"en") === "1.5 KB"`, `formatBytes(1024*1024,"en") === "1.0 MB"` and `formatBytes(1024*1024,"es") === "1,0 MB"` (Spanish locale uses the comma decimal separator). No React import, no dependencies, no date library.

### 5.2 Hook — `src/hooks/useFormatters.ts`
`const { language } = useI18n(); return useMemo(() => createFormatters(language), [language]);` Native `Intl` only; language values `en`/`es` are valid BCP 47 tags. The hook is never imported from a non-React module.

### 5.3 Domain adoption (public signatures unchanged)
- `callFormatter.ts`: `formatDuration` delegates to core `formatDuration`; `groupCallsByDay`/`formatCallTimestamp` delegate their `Intl.DateTimeFormat` calls to core `formatDate`/`formatTime` while keeping injected `now` and `DayLabels`.
- `formatChatTimestamp.ts`: delegate time/yesterday/day formatting to core; keep null/invalid → `""`.
- `formatMessageTime.ts`: `formatMessageTime`/`dateLabel`/`formatBytes` delegate to core; keep `dateLabel` capitalized output via a local capitalize-first helper over core relative output, documenting the deliberate difference from raw `Intl.RelativeTimeFormat` casing.

### 5.4 DOM + storage contract for the inline script and provider
Exact keys (prefixed by `src/lib/preferences.ts`): `silverchat_theme` (`light|dark|system`, default `system`), `silverchat_accent` (six values, default `blue`), `silverchat_language` (`en|es`). **The `silverchat_language_chosen` marker is removed entirely.** Background keys (`silverchat_chat_background:<ownerId>`, `silverchat_chat_background_dim:<ownerId>`) are not read or written by the script.

Behavior: wrap everything in `try/catch`; resolve system via `matchMedia("(prefers-color-scheme: dark)")`; validate every stored value against an allow-list; write `data-theme="dark"` for effective dark and **remove** it otherwise; remove all `theme-*` classes then add the valid accent; set `document.documentElement.lang` from the validated `silverchat_language` → normalized `navigator.language` → `en`. Place the script as a plain blocking `<script>` immediately inside `<head>`, before the SEO sentinel block and before Vite-injected stylesheet/module tags.

Provider alignment: `theme-provider.tsx` uses the same `data-theme` rule and attaches the media listener only for `theme === "system"` with proper cleanup; accent effect unchanged; `writePreference` unchanged. `globals.css` loses the `@media (prefers-color-scheme: dark) { :root:not([data-theme]) }` fallback so an OS-dark environment cannot override an explicit Light theme.

Language alignment (`AUD-025` revised `OQ-01`): `src/lib/language.ts` exposes `readStoredLanguage()` (allow-list validated single key) and `storeLanguage()`; `i18n-provider.tsx` resolves `readStoredLanguage() ?? detectDeviceLanguage()`, writes the key on explicit choice **and** when an authenticated account value is applied, and on sign-out writes and applies the device language so a second account never inherits the first account's stored value.

### 5.5 Account switch and offline preservation
Keep `PreferencesProvider`'s `key={user?.id ?? "guest"}`, `withOfflineFallback`, `attachPostgrestStatus`, debounce/flush chain, and `ChatBackgroundProvider` completely intact. Only add tests around them; do not refactor them. Account language override continues to flow through `applyLanguage`, which now also writes the single `silverchat_language` key; sign-out resets that key to the device language, closing the stale-language bleed path without any marker.

## 6. Alternatives considered

- **Adopt `i18next` (Prompt 14 literal):** rejected by `ADR-002` — three unused packages, parallel JSON tree, high regression risk, violates zero-dependency decision.
- **Put `Intl` logic directly in each domain formatter:** rejected — duplicates logic and reintroduces drift; pure core + hook gives one implementation for React and non-React callers.
- **Set `data-theme="light"` explicitly:** rejected — `:root` is the light source of truth per `globals.css` and roadmap §16; removing the attribute also lets the existing pre-provider `@media` fallback work correctly.
